# AGENTS.md — Instructions for AI assistants

This file tells AI assistants (ChatGPT, Claude, Copilot, Cursor, Codex, Gemini …) how to help in this repository.
Coding agents read it automatically. For web chats, attach or paste this file at the start of the conversation.

## Project
University group project (Introduction to Cyber Security, 2026/2027): a security assessment of
**OWASP Juice Shop v20.2.0** against all **OWASP Top 10:2025** categories, plus write-ups of
**PortSwigger Web Security Academy** labs. Deliverables: a 5–7 page IEEE paper, a presentation/demo,
and an assessment dashboard that reads the finding files.

Team members are mostly new to web security and Git. They often write to you in **Turkish**:
reply in Turkish, but **everything written into repository files is in English**.

## Hard rules
1. **Never fabricate.** Do not invent steps, payloads, requests, responses, screenshots, results or CVSS inputs
   that the user did not actually perform or observe. If information is missing, ask the user for it
   (e.g. "What request did you send? What did the response contain?"). A finding must describe what really happened.
2. **Authorized targets only.** Testing guidance applies only to Juice Shop on `http://127.0.0.1:3000`
   and PortSwigger Academy lab instances. Never suggest testing any other host (university systems, public sites, etc.).
   See `docs/ethics.md`.
3. **Do not set `status: reviewed`.** Only a second team member sets it after reproducing the finding.
4. **Only touch the user's own files**: their findings, their evidence, `progress/<their-name>.json`.
   Do not edit other members' files, `findings/_TEMPLATE.md`, `scripts/`, `.github/`, or `docs/` unless the user explicitly asks.
5. **Never hand-edit `progress/*.json`.** They are generated by `python scripts/progress.py save <name>`.
6. **Own words.** Do not copy text from PortSwigger solutions, the "Pwning OWASP Juice Shop" book or other write-ups.
   Explain concepts freshly; cite sources in *References* instead.
7. **No invented references.** Only cite sources that exist (OWASP Top 10:2025, OWASP Cheat Sheet Series,
   CWE, PortSwigger Academy topic pages, NIST). If unsure a URL exists, say so instead of guessing.

## Finding conventions
**File name:** `<SRC>-<OWASP>-<NNN>-<slug>.md`
- `SRC`: `JS` (Juice Shop, in `findings/juice-shop/`) or `PS` (PortSwigger, in `findings/portswigger/`)
- `OWASP`: `A01` … `A10`
- `NNN`: 3-digit sequence within that category and source (next free number)
- `slug`: lowercase words joined by hyphens, e.g. `JS-A01-001-basket-idor.md`

**Evidence:** `evidence/<source>/<ID>-<n>.png` (png/jpg/gif/webp, ≤ 5 MB), e.g. `evidence/juice-shop/JS-A01-001-1.png`.
List every image in the `evidence:` front-matter field and link it in the *Evidence* section as
`![Step 1](../../evidence/juice-shop/JS-A01-001-1.png)`.

**Front matter** (all fields required; keep field names exactly as in the template):
| Field | Allowed values / format |
|---|---|
| `id` | Same as the file name prefix, e.g. `JS-A01-001` |
| `title` | Short English title |
| `source` | `juice-shop` or `portswigger` (must match folder) |
| `target` | Juice Shop: `"Juice Shop v20.2.0 / <METHOD> <endpoint or page>"`; PortSwigger: lab name + URL |
| `owasp` | `A01`…`A10`, must match the file name |
| `cwe` | `CWE-<number>` |
| `severity` | `critical` / `high` / `medium` / `low` / `info` — must match `cvss_score` |
| `cvss_vector` | Starts with `CVSS:3.1/` |
| `cvss_score` | 0.0–10.0 |
| `tester` | The team member's name (the person who actually did the test) |
| `tools` | What was actually used, e.g. `DevTools, Burp Repeater` |
| `date` | `YYYY-MM-DD` |
| `status` | `draft` / `confirmed` (never `reviewed`, see hard rules) |
| `evidence` | YAML list of evidence paths; at least one if `confirmed` |

**Severity ↔ CVSS 3.1:** critical 9.0–10.0 · high 7.0–8.9 · medium 4.0–6.9 · low 0.1–3.9 · info 0.0.
Derive the vector from what was observed and explain each metric briefly in *Impact*.

**OWASP Top 10:2025 names:** A01 Broken Access Control · A02 Security Misconfiguration ·
A03 Software Supply Chain Failures · A04 Cryptographic Failures · A05 Injection · A06 Insecure Design ·
A07 Authentication Failures · A08 Software or Data Integrity Failures ·
A09 Security Logging and Alerting Failures · A10 Mishandling of Exceptional Conditions.
Juice Shop category → OWASP mapping lives in `scripts/progress.py` (`CATEGORY_TO_OWASP`) and `docs/owasp-mapping.md`.

## Writing style for findings
- English, concise, academic but plain. Past tense for what was done ("The login request was modified…").
- Sections in template order: Summary → Attack concept → Steps to reproduce → Evidence → Impact → Detection → Mitigation → References.
- *Steps to reproduce*: numbered, exact, repeatable by a teammate; name the tool per step ("DevTools → Network").
  Include the real request/payload in a code block.
- *Mitigation*: concrete fix for this case + link to the relevant OWASP Cheat Sheet.
- Aim for quality over quantity: understanding the weakness matters more than the number of exploits.

## Commands
```bash
docker compose up -d                        # start Juice Shop on http://127.0.0.1:3000
python scripts/validate.py                  # must print "Kontrol gecti" before committing
python scripts/progress.py save <name>      # save challenge progress
python scripts/progress.py status           # team progress per OWASP category
```
Windows: use `py` if `python` is not found.

## Workflow
Branch per finding (`<name>/<short-desc>`) → add finding + evidence → `python scripts/validate.py` →
commit → push → pull request. `main` is protected: PRs need the `validate` check and one approving review.
If `validate.py` prints `[HATA]` lines, fix each one; the message says what is wrong.

## Helping beginners
- Explain security concepts step by step, in Turkish if the user writes Turkish.
- Guide the user to find and verify the issue themselves rather than handing over full challenge solutions
  when they are learning; they must be able to explain the finding in the presentation.
- For Git questions, prefer GitHub Desktop instructions (see `BASLANGIC.md`).
